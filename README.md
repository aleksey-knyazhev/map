# Наземная станция управления

Проект демонстрирует интерактивную карту на связке:

- Java + Micronaut backend
- PostgreSQL для хранения точек карты
- React + Leaflet frontend

## Принятое решение по оптимизации

Карта работает от текущего центра - как от реперной точки. Frontend отслеживает центр карты и масштаб, а backend по этим значениям рассчитывает область предварительной загрузки точек.

Frontend отправляет на backend только три параметра:

- `centerLat` - широта центра карты
- `centerLng` - долгота центра карты
- `zoom` - текущий масштаб

Backend рассчитывает прямоугольник pre-fetch вокруг этого центра. И возвращает только те точки, которые попадают в рассчитанные границы, подходят под текущий zoom - но с учетом коэффициента pre-fetch
 

## Pre-fetch область

Размер области предварительной загрузки больше видимой области карты.
Для простоты эксперимента, экран пользователя Наземной станции управления - принят квадратной формы (некий аналог "сферический экран в вакууме")

Текущее значение коэффициента:

```text
PREFETCH_MULTIPLIER = 2.5
```

Это означает загрузку области размером 250% от расчетной высоты экрана карты

## Когда происходит новая загрузка

Frontend не делает запрос на каждое движение карты. Повторный pre-fetch запускается в случае, когда:

- изменился `zoom`
- центр карты сместился больше чем на 50% от расчетной высоты экрана

Это так же параметризовано в константе:

```text
MOVE_THRESHOLD_RATIO = 0.5
```

Данные меры снижают количество запросов к backend, при активном перемещении карты

## Визуализация

Легенда к карте:

- поле точек, полученных из backend
- красной пунктирной рамкой обозначена текущая pre-fetch область, для которой backend вернул поле точек
- контур iPad-подобного планшета - абстрация, символизирует экран Наземной станции управления
